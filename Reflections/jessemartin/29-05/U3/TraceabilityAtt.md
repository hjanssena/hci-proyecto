Considering the traceability of our system's operability, we did leave some level of definition in the
repo.

All the attributes we chose came from the same software standard, the ISO 25010 from 2023. Then, we
formulated and layed out the requirements within our scope that fit in these attributes and these very
requirements were the ones that were focused on during design and implementation.

We set 6 metrics that measured each attribute through 3 scenarios made specifically for UX testing.
These metrics ranged from number of wrong turns, alerts and buttons pressed to know precisely how
fair was the system's design. We used AI to decide these metrics.

For example, we measured wrong turns while doing the activity of cloning events to see how easy it
was for the user to locate and successfully clone this feature.

We could have considered other indicators like time to restore/undo actions, which we didn't consider
while making the scenarios. Not that we could've used time specificaly but something along that line
would've been interesting to consider.
